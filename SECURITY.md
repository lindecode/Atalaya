# Seguridad

## Reportar una vulnerabilidad

No publique inicialmente vulnerabilidades explotables, secretos ni datos de otros
usuarios en un issue. Repórtelos de forma privada mediante GitHub Security
Advisories del repositorio oficial. Incluya versión, impacto, reproducción mínima
y mitigaciones conocidas, pero elimine datos personales y credenciales.

Se acusará recibo cuando exista capacidad de mantenimiento; este proyecto no
promete un SLA para la edición Community. Los clientes con soporte se rigen por
su contrato.

## Alcance

Son especialmente relevantes la exposición fuera de loopback, ejecución de
comandos, evasión del harness del LLM, inyección en RAG, acceso indebido a SQLite,
filtración de datos, verificación de paquetes y elevación de privilegios.

Atalaya observa y recomienda: una alerta o ausencia de alertas no demuestra por
sí sola que un equipo esté comprometido o limpio.
